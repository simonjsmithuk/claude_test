## What Was Implemented

### 1. JiraClient Write Methods ([agents/jira_client.py](agents/jira_client.py))

Added three new methods for writing data to Jira:

#### `add_comment(ticket_key, comment_text)` → bool
Posts a comment to a Jira ticket using the REST API v3. Formats text as ADF (Atlassian Document Format).

```python
success = jira_client.add_comment("AIDAT-1", "Specification:\n\n...")
# Returns True if comment added, False on error
```

**Key features:**
- Formats plain text as ADF paragraphs
- Returns 200/201 status codes as success
- Logs errors and returns False on failure
- Uses JIRA_EMAIL and JIRA_API_TOKEN from environment

#### `create_subtask(parent_key, summary, description)` → Optional[str]
Creates a Jira subtask under a parent issue.

```python
subtask_key = jira_client.create_subtask(
    parent_key="AIDAT-1",
    summary="Fix axios interceptor closure bug",
    description="Priority: high\n\nUpdate axiosInstance to read token..."
)
# Returns "AIDAT-2" on success, None on failure
```

**Key features:**
- Extracts project key from parent (e.g., "AIDAT-1" → "AIDAT")
- Formats description as ADF
- Returns the new subtask key (e.g., "AIDAT-2")
- Logs each subtask creation

#### `transition_issue(ticket_key, transition_name)` → bool
Transitions a ticket to a new status (e.g., "Estimated", "In Progress", "Done").

```python
success = jira_client.transition_issue("AIDAT-1", "Estimated")
# Returns True if transitioned, False if transition not found or failed
```

**Key features:**
- Fetches available transitions dynamically via GET `/rest/api/3/issue/{key}/transitions`
- Finds transition ID by name (case-insensitive)
- Logs available transitions if requested transition not found
- Returns 204 status as success

### 3. Bug Fixes

#### Fixed: `'JiraPlanningOrchestrator' object has no attribute 'jira_client'`
**Problem:** JiraClient was created as a local variable in `_read_jira_ticket()`, not stored as instance variable.

**Fix:** Changed line 235 from:

```
To:
```python

```

**Fix:** Added multi-level parsing:
```python

## Troubleshooting

### "Failed to add comment: 401"
**Problem:** JIRA_API_TOKEN is invalid or expired.

**Solution:**
1. Generate a new API token at https://gdslink.atlassian.net
2. Update `~/.bashrc`: `export JIRA_API_TOKEN="ATATT3xFfGF0..."`
3. Reload: `source ~/.bashrc`
4. Restart VS Code

### "Transition 'Open' not found"
**Problem:** Your Jira workflow doesn't have a transition named "Open".

**Solution:**
1. Check the log for available transitions: `Available: ['Estimated', 'Reopen', ...]`
2. Update [config/agents.yml](config/agents.yml#L74) with a valid transition name
3. Re-run the orchestrator

### "Failed to create subtask: Issue type 'Sub-task' does not exist"
**Problem:** Your Jira project doesn't have "Sub-task" issue type enabled.

**Solution:**
1. Go to Jira Project Settings → Issue Types
2. Enable "Sub-task" or change `create_subtask()` call to use your custom subtask type

### "Failed to parse taskplan JSON"
**Problem:** Taskplan format doesn't match expected JSON structure.

**Solution:**
1. Check the taskplan file: `cat .sdlc_runs/jira_aidat-1_*/taskplan.json`
2. Verify it's valid JSON
3. If it's wrapped in markdown code fences, the parser should handle it
4. Check logs for "First 500 chars" to see what's actually there
